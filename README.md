# My Office

适合 Chi 工作流的本机像素办公室试用版。当前版本 `0.2.0`，界面仅展示真实 Copilot hooks 观测。2026-09-20 用户选择接入当前 Windows 用户的全部本机项目，**仅保留元数据，不转发或保存请求正文**。VS Code 原生 Chat 与 Copilot CLI／SDK 的用户级配置已分别加入并备份；另一个项目的 VS Code 内置 CLI／SDK 会话已通过真实投递和页面展示验收。独立终端 CLI 与传统 Chat 尚未分别实测，不据此保证每个窗口均已接入。已移除来源切换、演示和手动任务入口。**不连接 ADO、M365 或 Obsidian**。

## Windows 桌面版

双击 [My Office.exe](<desktop/My Office.exe>)，或使用根目录的 [start-desktop.cmd](start-desktop.cmd)。桌面版采用 Electron，在独立的 Windows 窗口中显示办公室，不会打开浏览器，没有地址栏；运行时不需要另外启动终端。它仍在本机回环地址运行桥接接收器，**不是云服务，也不向外部站点加载页面**。

- 重复打开只唤起已有桌面窗口，不会出现多个桥接所有者。
- 如果网页版服务已经运行，桌面版验证后连接它；关闭桌面窗口不会结束该外部服务。
- 如果服务由桌面版启动，关闭窗口会一并停止它并清理桥接描述文件；内存观测按原规则清空。界面的“停止本机服务”仍需确认，停止桌面版自己启动的服务后窗口会退出。
- 原有任务文件、会话分类和 hooks 路径保留，不自动修改 VS Code／CLI 用户设置。当前构建绑定本项目位置，移动 EXE 不影响连接，但不要删除或移动原项目；项目搬家后重新生成 hooks 并重新构建桌面程序。
- 浏览器版与桌面版的昵称／职责存储相互独立，不自动读取浏览器配置。桌面版自己的设置保存在 `%APPDATA%\My Office`，同样按本机服务地址区分端口。
- 当前是本机用的未签名便携程序，不需要管理员权限、不安装系统服务、不设置开机自启。若组织策略禁止运行，请遵循组织要求，不关闭系统安全防护。

开发与重新打包：

```powershell
npm --prefix .\app ci
npm --prefix .\app run desktop
npm --prefix .\app run build:desktop
```

输出位于 `desktop\My Office.exe`。便携包包含运行时和界面，不包含任务文件、桥接令牌或浏览器数据；只附带本机项目位置，以继续使用已配置的 hooks。原有 hooks 进程仍使用本机 Node.js。Electron 比普通脚本体积更大，首次启动需解压运行时。

2026-09-24 桌面版验收：80 项自动化测试通过；实际运行了最终便携 EXE，确认窗口和像素画布显示、桥接连接、重复启动仅保留一个窗口，以及关闭时只停止桌面版自己启动的服务。任务文件哈希保持不变。便携包约 121 MiB；本次构建使用 `ELECTRON_BUILDER_COMPRESSION_LEVEL=3` 缩短压缩时间，默认的高压缩构建可能更慢。

## 浏览器版（保留兼容）

当前实例的地址为 <http://127.0.0.1:19000>。只有服务运行时才能打开。

以后可以双击 [start.cmd](start.cmd)，或者在工作区终端执行：

```powershell
node .\app\src\server.mjs
```

启动窗口会显示实际地址，双击启动还会在默认浏览器打开页面。默认端口为 19000，占用时在后续 20 个本机端口内选择，不结束其他进程。首次启动后保留服务窗口；关掉浏览器不会停止服务。服务已经运行时，再次双击会校验并打开已有实例，新启动窗口正常退出，不会创建第二个桥接所有者或显示错误堆栈。终端命令也会复用已有实例并显示地址；加上 `--open` 可自动打开浏览器。

启动会先检查桥接描述文件，再绑定端口。异常退出后遗留的 PID 可能已被 Windows 分配给其他程序；若保存的本机端口明确拒绝连接，启动会自动清理旧描述文件并恢复服务，不会结束该 PID 对应的进程。若端口仍接受连接，启动器会用本机桥接令牌验证已有服务，再复用原地址；兼容旧服务的验证请求是必定被校验拒绝的空事件，不会创建或更改观测记录。仅有端口占用并不代表它是 My Office。地址无效、令牌不匹配、检查超时或其他检查错误时会明确报错并保留描述文件，不会强行接管。代码调用 `startOffice` 仍保持独占启动语义；复用不会更新运行中服务的源码或配置，应用更改须先停止原实例再启动。

停止方式：页面左侧的“停止本机服务”并确认，或者在启动终端按 `Ctrl+C`。窄屏会折叠左侧系统信息，此时使用终端停止。

不需要管理员权限，不会安装服务、添加防火墙规则或设置开机自启。2026-09-20 经用户分步批准，先配置当前工作区 hooks，随后迁移到 VS Code 和 CLI／SDK 各自的用户级配置，并备份、移除本项目重复的观察 hook；保留其他设置和已有 hooks，不修改权限、审批或组织策略。公司准入及目录同步/备份策略仍未核实。

**运行中的服务不会因改源码自动升级。** 发送器遇到 v1 描述文件时，只发送旧服务支持的字段、只允许原工作区的 VS Code 事件，并停止发送请求摘录或分类新字段；旧服务须重启才能切换为 v2。旧服务内存中已经收到的摘录不会因代码修改被删除，但新界面不会显示它们，重启后清空。本次接收端已是 `all-local` / `metadata-only`，跨项目 SDK 事件已接收，无需为添加用户设置而重启；尚未实测的其他客户端仍须分别验证。

### 采集范围与退出

- hooks 输入经 stdin 在内存中解析；新请求仅用于本机规则分类，**不提取或发送任何请求摘录**。新服务的接收白名单拒绝 `prompt`、`requestExcerpt`、原始路径等正文/路径字段。
- 工具参数、返回正文、错误正文、委派内容与 transcript 路径均不转发、不落盘，不读取 transcript。保留项目目录末级名称、工作区/会话/子 Agent 的 SHA-256 标识、客户端、分类枚举、事件类型、受限工具名和时间；完整项目路径不进入事件和页面。
- 观测仅存本机服务内存，服务重启清空；本机手动分类覆盖和人物介绍独立保存。新请求不会形成任务正文，也不使用外部模型或接口。
- `all-local` 接受当前平台的本机绝对 `cwd`；`workspace` 限定为原根目录。缺少可靠身份、工作目录或合法时间时不猜测。相同项目名用工作区哈希区分，相同会话 ID 在 VS Code 和 CLI 中不合并。
- 桥接器使用独立令牌；令牌不能修改手动任务、演示或停止服务，网页令牌不能写入 hook 事件。令牌在启动时随机生成、服务退出时移除。
- 运行时会在 app 的被忽略本地目录生成 bridge 连接描述文件，含本机地址、工作区根路径和令牌。不要分享、提交、截图或同步该文件。此工具只面向同一 Windows 用户，不防御具有同一用户权限的恶意进程，也不声称实现了跨用户沙箱。
- 每次 hook 最多读 1 MiB，内部总时限 1.4 秒（另有 Node 启动开销），请求时限 650 ms；正常、坏输入或服务不可用均输出 `{}` 并退出 0。不存在 approve/deny/block 或模型上下文注入。
- 停止服务后 hooks 仍被调用但不再转发。彻底停用时，将活动配置文件扩展名从 `.json` 改为 `.json.disabled`，再确认 `/hooks` 中不再加载；仅删除本项目配置即可卸载，不改变其他 hooks。
- 这些 hooks 为 VS Code Preview 能力，格式/行为可能变化。只观察本机批准的新事件，无历史补读和离线重放。

官方依据：[VS Code Agent hooks](https://code.visualstudio.com/docs/agent-customization/hooks)、[VS Code Hooks reference](https://code.visualstudio.com/docs/agents/reference/hooks-reference)、[Copilot CLI hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference)。

### 工作分类

收到新请求时，桥接器只在内存中按明确关键词推荐为 DM 工程、周报/月报、知识整理或代码与自动化，然后仅发送分类结果；请求正文仍不转发、不保存。没有匹配项时归入代码与自动化。分类是本机规则推荐，不是 AI 对工作内容的结论。

在人物详情的“隐私设置”区域点击当前分类可以手动修改。手动选择按 Copilot 会话保存在本机，优先于后续自动推荐，并同时用于该会话的子 Agent；选择“自动推荐”可取消覆盖。分类只影响 My Office 的展示和筛选，不改变 Agent 的职责、行为或权限。

### VP 办公室与只读 Copilot 观测

- **无办公室审批操作**：页面不提供批准、拒绝、请进、已阅、下一位或本地排队功能，也不向 Copilot 写回任何审批结果。审批、拒绝、追问和继续执行全部在 VS Code 的 Copilot 界面完成。
- **只依赖真实事件**：Agent 位置、状态气泡、详情和时间线只来自当前 Copilot hooks 事件。`Stop`、`SubagentStop` 和 `SessionEnd` 仅显示「本轮结束」，不会转换成待审批或待查看。
- **证据不足就不显示**：当前接入的 hooks 没有明确审批请求/审批结果事件，因此办公室不会显示“等待审批”队列。以后只有在客户端提供可验证的只读审批状态时，才可被动展示，仍不在办公室提供操作按钮。

- **VP 视觉保留**：Chi 的办公室和专属人物继续保留，固定 Chi 不占六个 Agent 场景名额。点击场景人物仍只打开观测档案，不执行审批。

### 自定义人物介绍

选择人物，点击右侧头像旁的「编辑人物介绍」，填写昵称（最多 32 字）和职责（最多 160 字）并保存。留空使用默认值，也可点击「恢复默认介绍」只清除此人物的备注。

- 经用户确认，**仅昵称和职责**保存在当前浏览器的 `localStorage`，键为 `my-office.character-profiles.v1`。不上传到服务端，不包含请求摘录、工具事件、会话令牌或任务状态；请勿在介绍中填写敏感信息。
- 介绍按「来源 + 执行实例 ID」关联，不按姓名合并。新聊天、新任务或不同来源不会自动继承同名人物的介绍；它不是给真实 Agent 设置角色、系统提示词或权限。
- 刷新及同地址服务重启后介绍仍在；只有同一执行实例再次出现时才会匹配。不同浏览器、端口、`localhost` 与 `127.0.0.1` 不自动共享；隐私模式、浏览器清理或组织策略可能影响保留。
- 同一浏览器同源的多个标签页通过存储事件同步。保存失败会明确提示，禁止使用存储或存储损坏时不会假装保存成功，也不会自动覆盖旧内容。
- 最多保存 500 份介绍。当前不再显示的人物备注仍会保留；对话框中的「清除全部本机人物介绍」需要确认，且只删除该存储项，不删除任务或其他站点数据。
- 断线时仍可编辑本机介绍，但真实任务状态仍显示不确定，不因修改昵称或职责而变为在线、已批准或已完成。

## 能力与限制

- 工作分类包括 DM 工程、周报/月报、知识整理、代码与自动化；桥接器在内存中根据请求推荐，也可按会话手动覆盖。没有对应真实事件的分类计数为零，不创建虚构员工。
- 场景最多显示六个执行实例并包含当前选中人物，另有固定 Chi · VP 角色；本地来访者和队首优先显示，所有筛选结果都可在底部名册和列表中查看。
- 不会根据时间、工具次数或动画推算业务进度百分比。
- 内容审核与外部写回仍在原有工作流完成；这里没有“批准写回”功能。
- 历史手动任务文件 [app/.local/tasks.json](app/.local/tasks.json) 未由此次改动删除或修改，但不再展示。原后端最多 100 条、启动/写入时过滤超过 7 天记录的保留规则未变。
- 真实会话没有独立心跳；超过 5 分钟无新事件时，未结束的执行显示“状态未确认”，不等于离线；已结束执行保留结束事实并标记记录过期。
- 时间线保存在内存中，最多 300 条，服务重启后清空；界面只显示其中的真实观测事件。
- 页面断线会显示“连接中断”，停止场景动画并禁用主要服务端写入按钮；重新连接时刷新状态和会话令牌。本机人物介绍不写入服务端，仍可编辑。
- 状态流按完整快照更新。快照超过流缓冲阈值时不会主动断线；慢连接排空前跳过中间快照，下一次广播发送最新状态，避免无界积压。
- 运行时不请求外部模型、CDN、遥测或第三方接口；只监听 `127.0.0.1`。这不是多用户隔离沙箱，也不是公司安全审批结论。
- 已实现有界事件去重和较旧事件不覆盖新状态；并非可靠消息队列，不补发丢失事件，同时间事件按固定优先级处理。每次运行最多 100 个 hook 执行实例，达到上限拒绝新实例；已知实例仍能更新。
- 真实观测仅保存在内存，服务重启后清空，收到下一条事件才重建。近期真实会话数只统计 5 分钟内收到事件的主会话，不代表窗口数、在线数或完成任务数。
- 真实记录以客户端和项目作为展示上下文，不显示请求摘录或历史目标；执行者仍以脱敏 ID 区分。CLI 工具失败/错误事件仅说明收到该类事件，不提供错误正文，不把它们当作整个任务失败。没有成果文件打开或远程接入功能。
